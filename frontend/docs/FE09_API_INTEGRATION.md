# FE-09 — Chuẩn bị tích hợp API thật

Cập nhật 17/11/2026. Rà soát source trên `dev`, HEAD `1946c1f`; có các chỉnh sửa tài liệu UI chưa commit được giữ nguyên.

**Đã hoàn thành lượt đối chiếu source và lập kế hoạch tích hợp. FE-09 chưa nghiệm thu đầy đủ:** auth, API lựa chọn cấu hình, workspace và dataset đăng nhập qua HTTP còn thiếu. Chưa gọi API thật, chạy solver, nạp SQL hay thay đổi DB trong lượt này. Các hợp đồng đề xuất bên dưới chưa phải endpoint đã triển khai.

Giao diện hiện tại và các chỉnh sửa được duyệt là chuẩn; không yêu cầu khớp hoàn toàn prototype. FE-09 không thay đổi UI hoặc tự chuyển nguồn dữ liệu sang API.

Quy ước đã xác định từ source: JSON nghiệp vụ snake_case, ngày `YYYY-MM-DD`, timestamp có offset, số tiết là số thập phân. Revision/source token/hash lấy từ server và coi là giá trị opaque. `null` tải hoặc dữ liệu năm thiếu không chuyển thành 0/PASS. ID phải dương và nằm trong miền số nguyên an toàn của JavaScript; nếu tương lai vượt miền này cần thống nhất encoding chuỗi hai phía.

Lỗi hiện có qua `ApiExceptionHandler`: `error, code, message`, chưa có map lỗi theo field. HTTP client giữ payload trong `ApiError.details` và Location. Xử lý 400 nhập sai, 401 khôi phục/đăng nhập lại, 403 thiếu quyền, 404 tài nguyên không tồn tại, 409 tải lại dữ liệu hoặc theo Location lượt đang chạy, 422 ràng buộc/ngữ cảnh, 503 thử lại có kiểm soát. Không replay mutation tự động sau 409.

## 4. Auth và quyền — đề xuất cần chốt

**Hiện trạng:** chưa có login controller hay Spring Security trong POM. `PrincipalPlanActorResolver` tạm ánh xạ `Principal.name` sang `user_account.login_name` ACTIVE. `AssignmentPlanRepository.canManage` yêu cầu cùng trường, role `ACADEMIC_MANAGER` và manager_scope bao phủ mọi khối của đợt suốt học kỳ. Role admin mock không tự có quyền quản lý plan; seed chỉ khai báo ACADEMIC_MANAGER và TEACHER. CRUD cũ chưa có bảo vệ auth toàn cục.

Đề xuất cho mô hình SPA cùng origin qua proxy: session cookie HttpOnly, Secure khi HTTPS, SameSite phù hợp; server bảo vệ CSRF cho thao tác ghi. Đây là đề xuất, chưa quyết định thay JWT hay triển khai endpoint mới.

| Quyết định / đầu ra cần chốt             | Đề xuất cụ thể                                                                                                                                         | Trạng thái                                |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------- |
| Backend auth: đăng nhập/khôi phục/logout | Đề xuất POST `/api/auth/login`, GET `/api/auth/session`, POST `/api/auth/logout`; thống nhất body/status/CSRF và lỗi phiên                             | Chưa triển khai/chưa chốt                 |
| Dữ liệu session                          | `account_id`, `login_name`, `school_id`, `teacher_id` nullable, roles/capabilities, phạm vi khối/năm/hiệu lực, ngữ cảnh được phép, thời điểm hết phiên | Cần backend xác nhận DTO và semantics     |
| Chọn vai trò                             | Server xác minh vai trò đã cấp; frontend dùng để điều hướng, không tự cấp quyền bằng accountId/role                                                    | Cần chốt vai trò admin và quyền CRUD      |
| Danh tính audit                          | Principal do middleware auth tin cậy cung cấp; thống nhất tiếp tục login_name hay đổi resolver sang ID                                                 | Chưa có middleware thật                   |
| Quyền dữ liệu                            | Backend kiểm tra cả read/write, list theo trường/phạm vi; TEACHER chỉ dữ liệu bản thân đã phát hành                                                    | CRUD/global auth và teacher API còn thiếu |
| Phiên frontend                           | Restore trước route nghiệp vụ; 401 xóa cache theo tài khoản, về login; 403 giữ phiên và hiển thị thiếu quyền; logout hủy query và dọn cache            | Triển khai sau khi chốt auth              |

Không tạo mật khẩu demo hoặc bật tài khoản DISABLED trong seed chỉ để vượt bước auth. Không thêm header giả mạo người dùng vào proxy. HTTP client hiện có `credentials: same-origin`; lựa chọn cookie và CSRF phải được kiểm chứng end-to-end khi backend triển khai.

## 5. Dataset tích hợp và mapping ID

`backend/sql/02_seed.sql` có tài khoản DISABLED/credential `!DEMO_DISABLED_NO_PASSWORD!`, dữ liệu nhiều khoảng hiệu lực và solver `DEMO_NOT_RUN`. Không dùng seed này làm bằng chứng đăng nhập/solver thành công. Không chạy lại seed trên DB đang dùng.

Dataset đề xuất `FE09_UNIFORM_V1` trên DB kiểm thử riêng, một khoảng hiệu lực đồng nhất 01/08–31/12/2026. Tham khảo fixture đầy đủ trong `RoundReadinessPostgresTest.fixture()` và `SolverSnapshotPostgresTest`: đây là fixture kiểm thử dùng Principal giả/credential không đăng nhập được, cần tách thành bộ nạp cho môi trường tích hợp và cấp tài khoản qua auth thật. Không sao chép nguyên các ID phụ thuộc seed 1/4 của test.

| Thành phần         | Yêu cầu bộ nạp và manifest                                                                                                                                                                                            |
| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Trường/năm/kỳ/đợt  | Tạo namespace riêng; ghi ID thực `school_id, academic_year_id, semester_id, round_id` và ngày hiệu lực; không ánh xạ từ nhãn demo.                                                                                    |
| Tài khoản/quyền    | Manager ACTIVE có ACADEMIC_MANAGER + scope toàn khối của đợt; thêm manager thiếu scope và teacher cho ca 403. Cấp credential qua auth đã chốt, không ghi mật khẩu trong manifest/tài liệu.                            |
| Lớp/môn/thành phần | Ít nhất hai lớp, một môn, hai giáo viên đủ điều kiện; lớp–môn có STANDARD và ENRICHMENT cùng khoảng để kiểm chứng khóa nhóm khác giáo viên. Ghi ID scope/applicability/component/demand thực.                         |
| Nguồn giáo viên    | Employment TEACHING, qualification VERIFIED, experience đã biết (0 phải là NO_EXPERIENCE), workload basis VERIFIED đúng cấp và hiệu lực.                                                                              |
| F/C/R và xác nhận  | Period đồng nhất; outside workload được xác nhận kể cả 0, inventory chứa đúng demand IDs; reduction/conversion rỗng được xác nhận rõ. Xác nhận scope, applicability, từng component và tập components sau khi tạo đủ. |
| Config/rules       | Tạo/tra bằng code + version rồi ghi ID thực, xác nhận và metadata policy. Tách nhãn ILLUSTRATIVE_MVP_V1/demo, giữ T=A+F+C+R; không coi trần minh họa là ngưỡng pháp lý.                                               |
| Plan/run/report    | Bắt đầu đợt chưa có plan để thử create; lưu ID/revision/token/snapshot từ response. Các ID run/report phát sinh qua API, không điền trước vào fixture.                                                                |
| Reset              | Bộ nạp/reset chỉ áp dụng namespace/DB kiểm thử đã xác định, có manifest ID và version; không truncate DB dev hay xóa volume.                                                                                          |

Manifest đầu ra cần có `dataset_version`, mã namespace, các ID trên, config/rule code+version+ID và thời gian tạo; không chứa credential. **Chưa có bộ nạp/manifest chạy thật trong FE-09 này.**

Các ca dữ liệu riêng có thể tái lập: readiness thiếu inventory/required component; thiếu phạm vi; nguồn đổi làm snapshot stale; hai phiên sửa cùng revision; một dòng batch không hợp lệ; không có ứng viên; tải năm thiếu. Queue full/cancel cần cấu hình kiểm thử có kiểm soát, không làm đầy hàng chờ môi trường dev dùng chung. Không kỳ vọng can_export/can_open_feedback hoặc validation toàn PASS khi còn thiếu dữ liệu năm/lifecycle.
